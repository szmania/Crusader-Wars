# Project Plan: CC-231 Disable Siege Button

## 1. Project Overview
- **Jira Ticket**: [CC-231](https://team-16702636586024.atlassian.net/browse/CC-231)
- **Problem Statement**: CK3 has a built-in mechanism that prevents sieging a settlement when the attacker doesn't have enough soldiers. Currently, the siege "Fight" button remains enabled even when the player lacks sufficient troops, leading to a CK3 error message. We need to disable the button proactively and show a tooltip explaining why.
- **Project Objectives**:
  - Disable the siege "Fight" button when the player has insufficient soldiers to assault
  - Add a tooltip on the disabled button explaining why (e.g., "Not enough troops to assault")
  - Ensure the button re-enables when sufficient troops are available
  - Maintain compatibility with existing mod files and siege window UI
- **Scope**: Update `ck3_mods/crusader_conflicts/` files only. No changes to C# backend or other mod systems.
- **Success Criteria**:
  - Siege button is visually disabled (greyed out) when insufficient soldiers
  - Tooltip appears on hover explaining the disabled state
  - Button re-enables when sufficient troops are available
  - No CK3 errors or crashes from the change
  - Passes ck3-tiger validation

## 4. Problem Analysis and Goals
- **Problems**:
  - Siege "Fight" button stays enabled even when player lacks sufficient troops
  - CK3 shows an error message instead of proactively disabling the button
  - Poor UX — player clicks button only to get an error
- **Goals**:
  - Proactively disable the siege button when insufficient soldiers
  - Provide clear feedback via tooltip on why the button is disabled
  - Improve user experience and reduce confusion
- **Why Needed**: Better UX alignment with CK3's built-in troop validation
- **Bottlenecks**: Need to understand existing siege window GUI and trigger logic

## 5. Architecture Overview
- **Components**:
  - Siege window GUI file (`.gui`) — contains the "Fight" siege button definition
  - Scripted trigger or effect — checks if player has enough soldiers for siege
  - Localization (`.yml`) — tooltip text for disabled state
- **Key Design Decisions**:
  - Use CK3's built-in `can_perform` or equivalent trigger on the button to disable it
  - Add tooltip text via localization that explains the disabled reason
  - Leverage existing CK3 siege validation logic rather than reimplementing

## 6. Implementation Phases
1. **Research Phase**: Identify the siege button GUI element and the trigger/effect that validates troop count
2. **Implementation Phase**: 
   - Add trigger to disable siege button when insufficient troops
   - Add tooltip text to localization files
   - Wire tooltip to the disabled button state
3. **Validation Phase**: Run ck3-tiger validation, verify no errors
4. **Review & PR Phase**: Code review, plan verification, create pull request

## 7. Risk Mitigation Strategy
- **Risk**: Breaking siege window UI — Mitigation: Make minimal changes, only to the button definition
- **Risk**: Compatibility with other mods — Mitigation: Use standard CK3 patterns
- **Risk**: Incorrect troop count validation — Mitigation: Leverage CK3's built-in validation
